Through Git Hub, you can create remote repositories, which allow for multiple different people, using different devices, to contribute to the same project. It is a vluable resource, free (Git hub is open source) and allows for the public to access your said repository.
When you are logged into Git hub website, you can create a new remote repository by clicking the "+" tab, and then you will see a "new repository" option.
Commands to execute for creating remote repositories:
'git remote' -> used to determine which remote repository the local repository is linked to.
'git remote add nameofremoterepo linkofrepositorythroughgithubsite' -> is the structure you want when linking the remote repository to the loal repository for the frist time. example: 
'git remote add remoteog1 https://github.com/jchiapp44/my-first-repo.git' -> will link my local repository to the first remote repository i created through git hub, its name wil be remoteog1.
'git push -u remoteog1 master' -> very first git push that will push all commits from local repository to the remote repo. -u flag is crucial in establishing the default remote repositor. It establishes master branch of remote repo as the default remote repository.

The 'git pull' command accomplishes two things in one: 'git fetch' and 'git merge'. the fetch downloads the new commits (from the remote repository via git hub) and the merge will insert those changes (join/merge) into the current local branch. 
POTENTIAL COMPLICATIONS TO 'GIT PULL':

proper vernacular: 'git push' is how local changes/commits reach the git hub remote repo, so although its essentially the same end result of merging local repositories, its considered pulling and not merging. 
'git push' -> updating remote repository with the changes/commits made from the local repo. 
'git pull' -> updating local repository with the changes/commits made from the remote repo via git hub website.
